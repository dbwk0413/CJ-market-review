# 제품 아이디어 시장 검토 워크보드

첨부한 흐름도를 바탕으로 만든 편집 가능한 첫 버전입니다. 실제 CJ제일제당 자료나 경쟁사 매출을 내장하지 않았습니다. **가상 예시 채우기** 버튼의 수치는 데모이며, 실제 판단에 사용하면 안 됩니다.

## 1. 컴퓨터에서 열기

1. 압축을 풀고 `cj-market-prototype` 폴더를 엽니다.
2. 폴더 안의 `index.html`을 더블클릭하면 브라우저에서 실행됩니다. 별도의 설치나 서버가 필요 없습니다.
3. 수정하려면 VS Code에서 **파일 → 폴더 열기**로 `cj-market-prototype` 폴더를 엽니다.
4. 왼쪽 목록의 `index.html`을 눌러 글자, 색상, 계산 로직을 수정하고 **Ctrl+S**로 저장합니다. 브라우저를 새로고침하면 변경 사항이 보입니다.

## 2. 사용하는 방법

1. 제품명과 비교할 시장 범위를 입력합니다. 예: `국내 냉장 즉석식품 중 한 끼 식사형 랩`.
2. 관찰한 사실을 적고, GIS에서 직접 조사한 입지 자료의 지표·기간·출처를 적습니다.
3. **같은 시장 범위, 같은 기간, 같은 매출 단위**의 1~3위 자료를 입력하고 자료 출처를 기록합니다.
4. 제품 1개당 예상 판매가와 제조원가를 입력하고 포함한 원가 항목을 적습니다.
5. **검토 결과 보기**를 누르면 입력한 매출 막대, 1위 매출/2·3위 매출 합계, 단순 차액과 제조원가율이 나옵니다.
6. **결과 텍스트 저장**을 누르면 현재 결과를 `.txt`로 내려받습니다.

매출 격차는 시장 진입 가능성을 확정하는 기준이 아닙니다. 전체 시장 매출, 성장률, 소비자 수요, 유통 비용, 물류·판촉 비용, 공급 능력 등을 별도로 확인하세요. GitHub Pages에서는 GIS 분석, 외부 데이터 수집, 출시 후 판매 데이터 연동을 서버에서 자동 실행할 수 없습니다. 현재 화면의 해당 칸은 조사 결과를 적는 메모입니다.

## 3. GitHub에 올리기: 웹사이트에서 파일 업로드

1. [GitHub](https://github.com/)에 로그인합니다.
2. 오른쪽 위 **+ → New repository**를 누릅니다.
3. 저장소 이름에 `cj-market-review`를 입력하고 **Public**을 선택한 뒤 **Create repository**를 누릅니다. 같은 이름이 이미 있다면 다른 이름을 써도 됩니다.
4. 저장소 첫 화면에서 **uploading an existing file**을 클릭합니다. 링크가 안 보이면 **Add file → Upload files**를 누릅니다.
5. 압축 파일 자체가 아니라, 압축을 푼 폴더 안의 `index.html`과 `README.md` **두 파일을 선택해 업로드**합니다. 업로드 후 파일 목록에서 `index.html`이 저장소의 최상위에 보여야 합니다. `cj-market-prototype/index.html`처럼 폴더 한 단계 아래에 두면 아래의 `/(root)` 설정과 맞지 않습니다.
6. 아래 **Commit changes**를 눌러 업로드를 확정합니다.

## 4. 공개 웹주소 만들기

1. 저장소 위쪽의 **Settings**를 누릅니다. 안 보이면 상단의 `…` 메뉴에서 찾습니다.
2. 왼쪽 메뉴 **Pages**를 누릅니다.
3. **Build and deployment → Source → Deploy from a branch**를 선택합니다.
4. **Branch**를 `main`, 폴더를 `/(root)`로 고르고 **Save**를 누릅니다.
5. 잠시 뒤 같은 **Pages** 화면의 **Visit site**를 누릅니다. 주소는 보통 `https://계정명.github.io/cj-market-review/` 형식입니다. 실제 계정명과 저장소 이름을 사용하세요.
6. 수정할 때는 저장소의 `index.html`을 열고 연필 모양 **Edit this file → Commit changes**를 누르거나, 수정한 파일을 다시 업로드합니다. 배포 반영까지 몇 분 걸릴 수 있습니다.

## 5. 자주 막히는 지점

- **404가 뜬다:** `index.html`이 저장소 최상위에 있는지, Pages가 `main`/`(root)`를 가리키는지 확인합니다. 배포가 끝날 때까지 조금 기다린 뒤 새로고침합니다.
- **코드만 보인다:** GitHub 저장소 주소를 열었을 가능성이 큽니다. **Settings → Pages → Visit site**의 주소를 여세요.
- **수정했는데 그대로다:** 변경 파일을 **Commit changes**로 저장했는지 확인하고 배포가 반영될 때까지 기다린 뒤 강력 새로고침(`Ctrl+F5`)을 합니다.
- **실제 시장자료가 자동으로 안 뜬다:** 이 버전은 수동 입력형입니다. 자동 수집에는 출처별 이용 조건 확인, 데이터 수집 코드, 서버 또는 예약 작업, 검증 절차가 추가로 필요합니다.

## 파일 구성

- `index.html`: 화면·스타일·계산 코드가 한 파일에 들어 있습니다.
- `README.md`: 사용법과 배포 설명입니다.

입력한 값은 서버에 저장되지 않습니다. 페이지를 닫거나 새로고침하면 입력값이 사라지므로, 필요한 결과는 **결과 텍스트 저장**으로 보관하세요.
